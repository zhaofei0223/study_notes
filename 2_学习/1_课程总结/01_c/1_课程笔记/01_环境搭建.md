# C 开发环境搭建

本人常用的系统为 Windows 和 linux ， 故对这两个系统进行了整理：

## Windows 安装开发环境

在 Windows 上安装 C 开发环境，主要有两条路线：一是装 Visual Studio 这种全能 IDE，二是用 MinGW 或 MSYS2 配 VS Code 的轻量组合。 新手图省心选前者，想轻量、灵活或习惯命令行选后者。

🖥️ 路线一：Visual Studio（推荐新手）

微软官方 IDE，自带 MSVC 编译器、调试器，装完即用，无需手动配环境变量。

1. 下载安装器：去 Visual Studio 官网下载社区版（Community），个人学习免费。
2. 选择工作负载：运行安装器后，勾选“使用 C++ 的桌面开发”，这是 C/C++ 核心组件，含编译器、Windows SDK 等。
3. 开始安装：安装包较大，默认占用约 10G 空间，可在安装器里改路径，然后点“安装”等待完成。
4. 验证：启动 VS，新建“空项目”，写个 Hello World 代码，点“本地 Windows 调试器”运行，输出正常即环境 OK。

> Visual Studio 是完整 IDE，功能强大但偏重；VS Code 只是轻量编辑器，需自行搭配编译器才能编译 C 代码。

⚙️ 路线二：MinGW + VS Code（轻量主流）

此组合占用小、启动快，也是目前较流行搭配。

1. 安装编译器（MinGW）：通过 MSYS2{id="entity_1"} 安装较方便。下载 MSYS2 安装包，一路下一步安装，注意安装路径不要含中文或空格。
2. 安装 GCC 工具链：安装完启动 MSYS2 终端，输入命令按回车更新软件包，再输入命令安装 MinGW 工具链（含 gcc.exe）。
3. 配置环境变量：找到 `mingw64\bin` 文件夹，复制完整路径，添加到系统环境变量 `Path` 中。
4. 验证编译器：打开 cmd，输入 `gcc -v`，若显示版本信息则配置成功。
5. 安装 VS Code 及插件：下载安装 VS Code，在扩展商店搜索安装 C/C++（微软官方）和 Code Runner 插件，即可获得语法高亮、代码补全和一键运行功能。

> 若下载 MinGW 压缩包手动解压，记得把解压后 `bin` 目录路径加到 `Path`，且路径保持纯英文。

📝 验证环境

无论哪条路线，写个简单程序测试：

```c
include <stdio.h>
int main() {
    printf("Hello World!\n");
    return 0;
}
```

保存为 `hello.c`，命令行执行 `gcc hello.c -o hello.exe` 再运行 `hello.exe`，输出 Hello World 即环境搭建完成。

## Linux 安装开发环境
在 Linux 上装 C 语言开发环境，核心就是装好编译器（gcc）、调试器（gdb）和构建工具（make/cmake）这几件套。不同发行版用不同包管理器，下面按最常见系统整理。

🐧 Ubuntu / Debian 系（apt）

1. 安装核心工具链：`build-essential` 这个元包会带上 gcc、g++、make 等基础工具，再补装 gdb 调试器。
```bash
sudo apt update
sudo apt install -y build-essential gdb
```
2. 验证安装：分别执行 `gcc --version`、`gdb --version`、`make --version`，能正常输出版本号就说明工具链没问题。
3. 可选：装 cmake 用于大型或跨平台项目，`sudo apt install cmake`。

🎩 Fedora / RHEL / CentOS 系（dnf / yum）

1. 安装工具链：Fedora 用 dnf，老版本 CentOS 用 yum，命令类似。
```bash
sudo dnf install -y gcc gdb make cmake
或者按软件包组安装，一次性带上更多开发工具
sudo dnf group install "Development Tools"
```
2. 验证安装：同样用 `gcc --version` 等命令确认。

🚀 Arch / Manjaro 系（pacman）

1. 安装工具链：Arch 用 pacman 直接装。
```bash
sudo pacman -S gcc gdb make cmake
```
2. 验证安装：版本命令确认即可。

📝 编辑器选择

装完工具链后，写代码还得有个编辑器，按上手难度分两条路：

- 零基础路线：用 `nano`，上手成本极低，`Ctrl+O` 保存、`Ctrl+X` 退出，三分钟就会。
- 进阶路线：用 `vim`，建议先跑 `vimtutor` 练起，每天 15 分钟，一周基本熟练。
- 图形化路线：不习惯终端编辑器的话，直接在 Windows 上用 VSCode 配 Remote-SSH 插件连虚拟机，既能享受图形化编辑，又能保证代码在 Linux 里编译运行。

✅ 验证环境：编译第一个程序

装完先跑个 Hello World 确认整条链路通没通。

```c
include <stdio.h>
int main() {
    printf("Hello, Linux C!\n");
    return 0;
}
```

编译运行：
```bash
gcc -Wall -Wextra -g -std=c11 hello.c -o hello
./hello
```

参数说明：`-Wall -Wextra` 打开常见警告（新手强烈建议一直开着），`-g` 生成调试信息（配合 gdb 用），`-std=c11` 指定 C11 标准。

> ⚠️ 运行当前目录的程序必须写 `./hello`，直接敲 `hello` 系统不会在当前目录找可执行文件，这是新手最容易踩的坑。

🛠️ 进阶工具：Make 和 CMake

写单文件程序直接 gcc 就够了，但项目一大就需要构建工具。

- Make：适合小型项目，通过 Makefile 手动维护规则，简单直接。
- CMake：适合跨平台和大型项目，自动生成 Makefile 等构建文件，更灵活强大。

CMake 的用法是先在项目根目录创建 `CMakeLists.txt`，然后：
```bash
mkdir build && cd build
cmake..
make
```

🔧 常见问题速查

- 头文件找不到：通常是缺 dev 包，Ubuntu 上一般就是没装 `build-essential`，补装即可。
- 链接报 undefined reference：最常见原因是拿 gcc 编译 C++ 代码却没链接标准库，换成 `g++` 或加 `-lstdc++` 参数。
- cmake 找不到编译器：先确认 `which gcc` 有输出，没有说明工具链没装好；装了还报错就显式指定路径，`cmake -DCMAKE_C_COMPILER=/usr/bin/gcc..`。
